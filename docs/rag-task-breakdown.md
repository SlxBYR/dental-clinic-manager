# RAG 第一版任务拆解

## 目标

在现有牙科诊所管理系统中加入第一版本地 RAG 能力，用患者档案、处置记录、预约记录和手动知识条目构建本地可检索知识库。第一版不强制接入 AI，不上传患者数据，先提供可用的本地检索和证据片段展示。

## 第一版范围

- 从现有患者数据生成 RAG 文档片段。
- 支持手动输入知识条目。
- 支持关键词检索，返回相关片段和来源。
- 在应用中增加 RAG/知识库页面入口。
- 保持本地运行，不引入外部 AI 服务。

## 暂不包含

- 向量 embedding 检索。
- 外部数据库同步。
- PDF、Word、图片 OCR 导入。
- AI 总结回答。
- 多用户权限和审计。

## 设计原则

- 患者主数据仍由现有 `clinicService` 管理，RAG 不成为新的权威数据源。
- 第一版索引可重建，不需要复杂迁移。
- 手动知识条目本地保存，后续可迁移到 SQLite 独立表。
- 搜索结果必须展示来源，避免让用户误以为系统给出了无依据结论。
- 医疗相关回答只做档案检索和资料归纳，不做诊断。

## 第三期：可选 AI

### 目标

在保持默认本地检索的基础上，允许用户主动开启 AI 回答。AI 只作为检索结果的总结层，不替代本地 RAG 检索；回答必须展示引用来源，无法找到证据时不能编造患者信息。

### 默认策略

- 默认关闭 AI。
- 未配置 Provider、API Key 和模型时，只显示本地检索结果。
- 开启前明确提示：患者姓名、电话、处置备注、预约信息等可能被发送到第三方服务。
- 每次 AI 回答都必须基于当前检索命中的片段。
- 回答区域必须显示引用来源，至少包含来源类型、标题、患者名或文件名。
- 医疗场景文案定位为“资料归纳”和“档案检索”，不输出诊断结论。

### 设置项

| 字段 | 说明 |
| --- | --- |
| `enabled` | 是否启用 AI 回答，默认 `false`。 |
| `provider` | AI 服务商，例如 OpenAI-compatible、自建接口、本地模型接口。 |
| `baseUrl` | 可选，自定义兼容接口地址。 |
| `apiKey` | API Key，后续应迁移到 Electron 安全存储。 |
| `model` | 模型名称。 |
| `sendPatientInfo` | 是否允许发送患者可识别信息，默认 `false`。 |
| `redactionMode` | 脱敏模式：关闭、基础脱敏、严格脱敏。 |
| `maxContextChunks` | 单次发送给 AI 的最大片段数。 |

### 脱敏规则

- 基础脱敏：隐藏电话中间位，患者姓名保留。
- 严格脱敏：患者姓名替换为患者编号，电话全量隐藏。
- 文件和手动知识条目按用户选择处理；含患者信息的文件默认走严格脱敏。
- AI 返回后，本地再把引用映射回真实患者和来源。

- 构建和类型检查通过。

## 第四期：外部数据库

### 目标

实现外部数据源 adapter 机制，先接入一个样例外部数据源，再逐步扩展同步、冲突处理和增量更新。外部数据库不直接覆盖本地患者主数据，必须经过预览、确认和冲突策略。

### Adapter 接口草案

```ts
export interface RagExternalSourceAdapter {
  id: string;
  name: string;
  kind: 'http-json' | 'sqlite-file' | 'custom';
  testConnection(config: RagExternalSourceConfig): Promise<RagExternalSourceStatus>;
  pull(config: RagExternalSourceConfig, cursor?: string): Promise<RagExternalPullResult>;
  mapDocument(raw: unknown): RagExternalDocument;
}
```

### 外部文档结构草案

```ts
export interface RagExternalDocument {
  externalId: string;
  title: string;
  content: string;
  updatedAt?: string;
  patientMatch?: {
    patientId?: string;
    name?: string;
    phone?: string;
  };
  metadata?: Record<string, string | number | boolean>;
}
```

### 样例数据源

第一版样例建议使用 `http-json`：

- 用户配置一个只读 JSON endpoint。
- 系统发送 `pull` 请求，返回文档列表。
- 每条外部文档进入 RAG 知识库，但不自动写入患者档案。
- 如果外部文档带患者姓名/电话，只做候选匹配，等待用户确认。

### 同步策略

- 全量同步：首次接入或用户手动重建时拉取全部外部文档。
- 增量同步：保存 `cursor`、`updatedAt` 或远端版本号，只拉取变化数据。
- 删除处理：外部源标记删除时，本地将对应 RAG 文档标记为不可检索，不立即物理删除。
- 重试策略：网络失败不清空旧数据，保留上一次可用索引。

### 冲突处理

- 外部数据和本地患者主数据分离保存。
- 外部文档命中患者时，只建立引用关系，不直接修改患者。
- 如果未来允许写入患者档案，必须提供导入预览：
  - 新增患者
  - 匹配已有患者
  - 字段冲突
  - 无法匹配
- 冲突策略必须由用户选择：跳过、作为知识条目保存、合并到患者备注、创建新患者。
